# infra-deadlines

**Доска сроков: что и когда выключают в крипто- и web3-инфраструктуре.**
Убранные эндпоинты, остановленные сети, урезанные бесплатные тарифы, снятые с
поддержки SDK — у каждой записи дата в UTC, минимальное требуемое действие и
ссылка на первоисточник, который это объявил.

**English:** [README.md](README.md) · **Español:** [README.es.md](README.es.md)

## Зачем это

Об отключении объявляют один раз, в чейнджлоге, на который никто не подписан, —
а потом оно происходит. Провал почти никогда не звучит как «мы не нашли обходной
путь». Он звучит как «мы не знали про дату». Эта доска — то самое чтение,
которого никто не делает, записанное.

Она ведётся руками, каждую неделю, для выпуска
[Infra Graveyard Weekly](https://ru.sepia.software/blog/series/infra-graveyard), и
опубликована здесь, потому что сам набор данных полезен отдельно от выпуска:

- Русский — <https://ru.sepia.software/blog/series/infra-graveyard>
- English — <https://sepia.software/blog/series/infra-graveyard>
- Español — <https://es.sepia.software/blog/series/infra-graveyard>

## Что скоро отвалится у меня

```bash
npx infra-deadlines                    # всё открытое, ближайшее первым
npx infra-deadlines --days 30          # только ближайшие 30 дней
npx infra-deadlines solana chainlink   # только записи, где это упоминается
npx infra-deadlines --json             # машиночитаемо
```

В CI — чтобы вам сказали, а не чтобы вы помнили:

```bash
npx infra-deadlines solana --fail-within 30   # код выхода 1, если что-то попадает в 30 дней
```

## Два правила, по которым доска ведётся

**Срок не считается закрытым по объявлению.** Он закрывается, когда источник
перепроверен и событие действительно наступило. Записи, у которых объявленная
дата прошла, а выключатель не щёлкнул, остаются открытыми и несут
`overdue: true` — это живой риск, а не забытая строка. Chainlink объявил три
фида на 2 сентября 2026 года; через двенадцать дней все три продолжали
обновляться внутри своего heartbeat, поэтому запись всё ещё открыта.

**Чего объявление не покрывает — не додумываем.** Если в уведомлении поставщика
ничего не сказано о судьбе средств в пуле, доска пишет, что объявление об этом
молчит, а не то, что мы предполагаем. Догадка, выданная за факт, хуже дырки:
дырку хотя бы идут проверять.

## Форма записи

```yaml
open:
  - id: solana-rent-phase-2
    what: "Solana rent reduction phase 2 (SIMD-0437-2): lamports_per_byte 6,333 -> 5,080…"
    deadline: 2026-09-15
    time: null              # источник назвал дату, но не время суток
    date_precision: month   # необязательное: источник сказал «середина сентября»
    action: "Replace hardcoded rent constants with getMinimumBalanceForRentExemption()…"
    source: "https://solana.com/upgrades/reduced-rent"
    source_quality: primary # primary | secondary
    first_issue: 6
```

У закрытых записей вместо `deadline` стоит `effective` — день, когда это
действительно произошло, — и `verified`, если проверка была только частичной.

`open` отсортирована по ближайшему сроку, `closed` — по недавно закрывшимся.
Оба порядка проверяются.

## Проверка доски

```bash
npm run verify     # отчёт
npm run check      # код выхода 1 при любой проблеме — для CI
```

Проверяются структура, формат дат, повторяющиеся id, порядок и, главное, не
висит ли что-то в `open` после своей даты без записанного вердикта. Последняя
проверка появилась потому, что 12 сентября 2026 года четыре строки неделями
стояли просроченными на публичной странице, а два события не были заведены
вовсе. Ничего не сломалось в коде — доску просто никто не прочитал.

**Чего проверка не делает:** не перепроверяет каждую запись по живому
источнику. Универсального способа нет: одна запись — чтение фида из сети,
следующая — REST-эндпоинт, следующая — блог поставщика, который с тех пор стал
JS-оболочкой без текста внутри. Эта сверка остаётся ручной и остаётся правилом
выше.

## Как пользоваться данными

```js
import { load, upcoming, daysLeft } from "infra-deadlines";

const board = load();
for (const e of upcoming(board, { within: 30 })) {
  console.log(daysLeft(e), e.id, e.action);
}
```

Или читайте `deadlines.yaml` напрямую — это весь набор данных, и базы за ним
намеренно нет.

## Поправки приветствуются

Неверная дата здесь хуже, чем её отсутствие. Если запись протухла, объявление
сдвинулось или выключатель так и не щёлкнул — заведите issue со ссылкой на
источник, и её сверят именно с источником, а не с предыдущей записью.
